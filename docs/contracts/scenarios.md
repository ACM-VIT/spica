# Contract v1 reference scenarios

Status: **proposed regression specification only**. There is no fake adapter, domain test suite or runtime behavior implemented by task 001. [Core v1](core.md) is normative; [immutable reference evidence](references.md) supplies provenance, not proof that Spica works. These twelve scenario families share one deterministic fixture and vary only the boundary under test. Parameterized branches below are required cases, not optional examples. Splitting every branch into a new end-to-end scenario would duplicate setup without improving the ownership oracle.

## Harness and counting conventions (future implementation)

Use a temporary fresh store/workspace and synthetic accounts, IDs, content and protocol observations. No legacy histories, auth or network inference. A controllable fake adapter records every call at a journal boundary and can stop immediately before/after commit, dispatch, acknowledgment and terminal observation. Reopen means constructing a new domain owner over the same store, not constructing new work. Simulated runtime process identity is independent of model identity. Gates after 001 must implement these controls, not substitute direct state mutation for command paths.

Count **actual fake calls**, not accepted intents: `O` new-session opens, `S` starts/generation attempts, `A` approval replies, `C` cancellation requests, `I` read-only outcome inspections, `T` reattachments to the same session, `D` steering/message deliveries. Counts are per fixture unless a row explicitly says delta. Discovery, queries and subscriptions are side-effect-free and excluded; native tool actions have a separately observed `X` counter. Every effectful call must have a prior committed EffectId; its order is asserted. A row's event count is for its named event kinds only (journal bookkeeping may add distinct events). Compare canonical stored content byte-for-byte, including Unicode. Replayed observations and receipts cannot create extra events of the same semantic kind.

Default fixture: one project P, registered workspace W with validated base/branch/checkout, idle thread H, runtime instance RI, app session RS mapped to upstream US, explicit synthetic account/model/provider/effort and capability revision. Session is already created (`O=0` during scenarios); new-session branches explicitly count opens. Root task R owns W and finite budgets, two child slots, depth one. All commands use unique IDs and current revisions unless testing duplicates/conflicts. All event queries use a captured baseline sequence. Source references use the anchors in [references](references.md); claimed T3 parallels are limited to observed behavior, never inferred recovery guarantees.

## Why this is the minimum meaningful set

S01 owns the happy-path identity/receipt oracle; S02 mutates delivery/preconditions without duplicating lifecycle tests. S03 owns permissions/cancel; S04 injects crash boundaries those happy paths cannot prove. S05 tests the public read seam and root lifetime, S06 bounds that seam under load. S07–S09 separate correlation, ownership races and cumulative accounting, each with a different failure oracle. S10 covers adapter capability/identity negotiation, S11 workspace/review authority, S12 provenance and the real-runtime implementation gate. Every case is needed; randomized schedules and soak tests may extend these later, not replace the exact counts.
