## Codex 0.163.0

First real runtime target: local `codex app-server` stdio JSONL, with supported runtime-owned ChatGPT sign-in. The host-tool evidence is version-specific, not inferred from mutable online docs:

- Full Rust [`ThreadStartParams`](https://github.com/openai/codex/blob/83086188ae0614bd882818ff1aa23f3194962012/codex-rs/app-server-protocol/src/protocol/v2/thread.rs#L57-L151) exposes `dynamic_tools` serialized as `dynamicTools`, explicitly annotated `experimental("thread/start.dynamicTools")`. This requires the client's `initialize.capabilities.experimentalApi` opt-in; negotiate/validate rather than assume. The checked-in stable generated [`ThreadStartParams.ts`](https://github.com/openai/codex/blob/83086188ae0614bd882818ff1aa23f3194962012/codex-rs/app-server-protocol/schema/typescript/v2/ThreadStartParams.ts) omits that experimental field. Stable schema absence alone would give the wrong capability conclusion.
- [`common.rs`, `DynamicToolCall`](https://github.com/openai/codex/blob/83086188ae0614bd882818ff1aa23f3194962012/codex-rs/app-server-protocol/src/protocol/common.rs#L1827-L1831) defines server-to-client `item/tool/call`. [`DynamicToolCallParams`](https://github.com/openai/codex/blob/83086188ae0614bd882818ff1aa23f3194962012/codex-rs/app-server-protocol/schema/typescript/v2/DynamicToolCallParams.ts#L4-L6) carries threadId, turnId, callId, namespace, tool and arguments. [`DynamicToolCallResponse`](https://github.com/openai/codex/blob/83086188ae0614bd882818ff1aa23f3194962012/codex-rs/app-server-protocol/schema/typescript/v2/DynamicToolCallResponse.ts#L4-L6) returns contentItems/success. RPC request correlation is distinct from a durable Spica command ID.
- Supported alternative configuration surface: pinned [`core/config.schema.json`](https://github.com/openai/codex/blob/83086188ae0614bd882818ff1aa23f3194962012/codex-rs/core/config.schema.json), `properties.mcp_servers` / `definitions.RawMcpServerConfig`: named servers with `command`, `args`, `env`, `cwd` for local process transport or `url`, `http_headers`, environment-backed header fields for HTTP; enabled/disabled tool lists and startup/tool timeouts. It describes servers Codex calls, not Codex itself acting as the Spica command owner. No real configuration was written.
- Source also separates `model` and `modelProvider`; `allowProviderModelFallback` is explicitly experimental in the full thread/start schema. Spica must compare requested and reported identity, not assume the runtime binary's name identifies its model or silently enable fallback.

**Unverified live gates:** initialization/version negotiation, experimental dynamic registration acceptance, actual invocation and result delivery, tool visibility to selected model, MCP discovery/policy, supported ChatGPT login/entitlement, permission routing, stream/interrupt/resume, late callback/disconnect reconciliation and identity reporting. Neither installed version nor source proves these. Capability `coordinator_bridge` remains unavailable until the adapter's disposable-project gate verifies a real bridge; MCP is an alternative to evaluate, not an automatic fallback that changes configuration or credentials.

## OpenCode 2.1.4

Second real runtime target: ACP candidate first, v2 API only for demonstrated gaps. The immutable implementation is the evidence for support:

- [`packages/cli/src/acp/agent.ts`](https://github.com/anomalyco/opencode/blob/68bc26b7da1990ce10ffecfbc1e09eb13aa5d824/packages/cli/src/acp/agent.ts#L68-L119) registers initialize, session/new, load, resume, list, close, fork, configuration selection, prompt and cancel. These are protocol handlers, not evidence all session operations meet Spica's recovery contract.
- [`ACPService.initialize`](https://github.com/anomalyco/opencode/blob/68bc26b7da1990ce10ffecfbc1e09eb13aa5d824/packages/cli/src/acp/service.ts#L106-L129) advertises ACP protocolVersion 1, loadSession, MCP `{http:true,sse:false}` and session capabilities. ACP protocol version 1 is **not** OpenCode API/runtime version 1. `supportedMcpServers` (243–253) rejects transports other than stdio and HTTP with an explicit error. No ACP-client-hosted MCP transport or SSE support is established; this pin explicitly excludes them from session input.
- [`ACPSessions.registerMcp` / `mcpConfig`](https://github.com/anomalyco/opencode/blob/68bc26b7da1990ce10ffecfbc1e09eb13aa5d824/packages/cli/src/acp/sessions.ts#L93-L108) maps session MCP inputs to `client.mcp.add({server,location:{directory:cwd},config})`; mapping at 195–208 converts HTTP URL/headers or stdio command/args/env. New/load/resume attach these servers. Directory-scoped registration is not proof of session-private authority: bridge credentials/context need explicit correlation and isolation verification.
- Persistent v2 config shape is [`ConfigMCP.Info`](https://github.com/anomalyco/opencode/blob/68bc26b7da1990ce10ffecfbc1e09eb13aa5d824/packages/schema/src/config/mcp.ts#L19-L22): `mcp.servers.<name>` plus optional timeout defaults, **not v1's flat `mcp.<name>` examples**. [`Mcp.LocalConfig` / `RemoteConfig`](https://github.com/anomalyco/opencode/blob/68bc26b7da1990ce10ffecfbc1e09eb13aa5d824/packages/schema/src/mcp.ts#L19-L66) define local command array/environment/cwd or remote URL/headers, disabled/codemode flags, timeouts and protocol selection. Default legacy negotiation differs from opt-in auto/required 2026-07-28. Do not force a newer MCP revision merely because source describes it.
- [`McpTool.layer`](https://github.com/anomalyco/opencode/blob/68bc26b7da1990ce10ffecfbc1e09eb13aa5d824/packages/core/src/tool/mcp.ts#L43-L93) discovers/registers MCP tools, checks `permission.assert` then calls `mcp.callTool` with sessionID; server errors become tool failures. This is a real runtime hook suitable to evaluate for delegate/message/wait/cancel/list, not a bridge implemented by Spica yet. Code Mode defaults are visible in schema/source; selected-model tool presentation must be tested rather than equated to direct tool invocation.
- [`ACPCapabilities.parse`](https://github.com/anomalyco/opencode/blob/68bc26b7da1990ce10ffecfbc1e09eb13aa5d824/packages/cli/src/acp/capabilities.ts#L3-L14) only enables native child session updates when the client explicitly opts into `opencode/child-session-updates`. Native child notifications are observations, not ownership of Spica's child tree. Session model selection is tracked separately from runtime/session identity in ACPSessions.

**Unverified live gates:** MCP handshake/tool discovery, stdio/HTTP bridge invocation, session-isolated caller authority, model/agent selection/reporting, permission policy and response correlation, cancellation terminality, resume versus history replay, reconnect registration cleanup, usage completeness and cross-runtime child recovery. No claim that ACP supports a generic in-process client tool callback equivalent to Codex dynamicTools is made; this evidence establishes MCP attachment instead. Runtime-provider credentials remain runtime-owned and were not inspected.

## Reference scenario inputs

These are concrete evidence-derived inputs for the normative scenario owner, not executed tests or a second set of acceptance rules. Core/scenarios decide exact IDs/status/error names.

| Input | Preconditions and action | Evidence-informed oracle to specify |
| --- | --- | --- |
| Receipt replay | Commit create/send intent; resend identical command after losing reply. Also reuse its ID against another thread/payload. | One accepted intent/effect; replay is not a second run; conflicting reuse is rejected. T3 receipt replay is narrower evidence than a full payload identity guarantee. |
| Stream/approval/reopen | Start run, stream text/tool items, suspend on native approval; disconnect/restart before response. | Preserve durable transcript/intent; do not fabricate approval completion or resurrect live-only RPC; reconcile or explicitly expire/unavailable. |
| Cancel race | Cancellation commits after effect claim but before external start; later duplicate/late completion arrives. | Domain chooses authoritative transition; cancelled intent is not newly dispatched, and acknowledged interrupt alone is not proof tools stopped. |
| Ambiguous effect | Crash after external child dispatch but before recording upstream ID/result. | Unknown/interrupted effect; no blind respawn. This is Spica policy, not a demonstrated universal T3 guarantee. |
| Duplicate delegation | Coordinator retries one correlated tool call with same durable delegation key. | Same task/receipt and no second child; RPC IDs alone cannot implement durable deduplication. |
| Concurrent children | Two attached children complete out of order while parent switches UI roots; one sends duplicate completion. | Correlate by task/run/upstream IDs; retain one terminal outcome each; UI does not own run lifetime or ordering. |
| Capability rejection | OpenCode receives SSE/ACP MCP input; Codex receives experimental registration without opt-in. | Explicit unsupported/experimental failure; never mark bridge supported merely because runtime is installed. |
| Runtime/model mismatch | Request named model/effort on one runtime; reported model differs or is unavailable. | Keep requested/reported values distinct; fail/stop per core instead of silently replacing model/runtime. |
| Pagination while mutating | Read history page, new stream events mutate projection, then use old cursor. | Apply Spica snapshot/expiry contract; no claim that T3's cursor supplies that invariant. |
| Recovery and ownership | Parent cancelled with attached and explicitly detached children; restart with a pending native approval and unknown spawn. | Core owns cancellation propagation/detach, subtree usage bounds and unknown reconciliation; adapter owns transport callbacks. Native child roster cannot substitute for durable app tree. |
